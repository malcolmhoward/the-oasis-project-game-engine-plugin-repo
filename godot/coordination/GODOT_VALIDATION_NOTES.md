# Godot Validation Notes

Issues discovered during headless validation of the OCP plugin scaffold against Godot 4.5.2.

**Date**: 2026-03-28
**Godot version**: 4.5.2 stable (headless mode)
**Validation command**: `godot --headless --import`

---

## Issue 1: Scaffold generated for non-existent Godot version

**Symptom**: `project.godot` declared `config/features=PackedStringArray("4.6")` but Godot 4.6 does not exist. Latest stable is 4.5.2.

**Root cause**: The scaffold was generated from a design session that referenced a GDQuest GitHub issue mentioning 4.6. This was a future/speculative version number, not a release.

**Fix**: Changed to `PackedStringArray("4.5")` and updated all documentation references from 4.6 to 4.5.

**Prevention**: Always verify the Godot version against the [releases page](https://github.com/godotengine/godot/releases) before setting `config/features`.

---

## Issue 2: SVG preload fails in headless mode

**Symptom**: `Parse Error: Preload file "res://addons/oasis_ocp/icon_ocp_peer.svg" has no resource loaders (unrecognized file extension).`

**Root cause**: Headless Godot has no image importers. `preload()` requires the resource to be importable at parse time.

**Fix**: Replaced `preload("icon_ocp_peer.svg")` with `null` in `oasis_ocp_plugin.gd`. The icon is optional — Godot's editor loads it when available.

**Prevention**: Never `preload()` image assets in plugin scripts that need to work in headless mode. Use runtime `load()` with a null fallback, or pass `null` for optional icons.

---

## Issue 3: GDScript `:=` type inference treated as error

**Symptom**: `Parse Error: The variable type is being inferred from a Variant value, so it will be typed as Variant. (Warning treated as error.)`

Affected ~30 lines across 6 files. The `:=` operator infers type from the right-hand side. When the RHS returns `Variant` (e.g., `Dictionary.get()`, `JSON.parse_string()`, `get_node_or_null()`), Godot 4.5 treats this as an error in strict mode.

**Root cause**: The scaffold used `:=` extensively, which is valid GDScript but triggers strict-mode warnings when the source type is `Variant`. Godot 4.5's default project settings treat these warnings as errors.

**Fix**: Replaced `:=` with `=` (untyped assignment) in the 3 demo controller files that were still failing. Also added explicit type annotations (`: String`, `: Dictionary`) where the type is known.

**Prevention**: In GDScript for Godot 4.5:
- Use `var x: String = dict.get("key", "default")` instead of `var x := dict.get("key", "default")`
- Use `var x = dict.get(...)` (untyped) when the return type varies
- Avoid `:=` with methods that return `Variant` (`Dictionary.get()`, `JSON.parse_string()`, `get_node_or_null()`)
- `project.godot` `[debug]` settings for warnings are NOT respected during headless `--import` — fixes must be in the code itself

---

## Issue 4: `.uid` and `.import` files generated by Godot

**Symptom**: After running `--headless --import`, Godot generates `.uid` files for every GDScript and `.import` files for assets (SVG, etc.).

**Root cause**: Godot 4.5 assigns unique IDs (UIDs) to all scripts and imports assets on first scan.

**Fix**: These files should be committed — they are required for Godot to reference resources correctly. The `.gitignore` should NOT exclude `.uid` or `.import` files.

**Prevention**: Run `godot --headless --import` before the initial commit so these files are included from the start.

## Headless Validation Command Reference

```bash
# Download Godot 4.5.2 (Windows)
curl -fsSL "https://github.com/godotengine/godot/releases/download/4.5.2-stable/Godot_v4.5.2-stable_win64.exe.zip" -o godot452.zip
unzip godot452.zip -d godot452

# Validate project (from the godot/ directory)
./godot452/Godot_v4.5.2-stable_win64_console.exe --headless --import

# Expected output (clean):
#   [ DONE ] first_scan_filesystem
#   [ DONE ] loading_editor_layout

# Check for errors:
./godot452/Godot_v4.5.2-stable_win64_console.exe --headless --import 2>&1 | grep -i "error\|failed"
```
